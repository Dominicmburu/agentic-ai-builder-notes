Week 3 · Lesson 15 · Project

Project: the Product Expert voice agent

Put Week 3 together: a voice agent that answers questions from your product data and declines the rest.

About 90 minutes to read Project Download the slides

The big idea

You will build a voice agent that knows your products. Ask it about a price and it answers correctly. Ask it about something outside the catalogue and it politely says no. Then you prove it works with a test.

The goal: at least 85% of in-scope questions answered correctly, and all 3 out-of-scope questions declined.

What you are combining

Your starting files

  • Products.xlsx: the product list to load into Supabase.
  • voice.html: a ready-made web page that hosts the voice agent so you can talk to it in a browser.

Use the files your teacher shares. If you do not have them yet, ask before you start.

Build it in order

  1. Load the data (Lesson 14). Create the table, load every product once with metadata, and run the 10-product retrieval test. Do not move on until at least eight of ten pass.
  2. Build the answering workflow. A Webhook node, an AI Agent with a chat model, and the vector store as a tool. Return the answer with Respond to Webhook.
  3. Write the grounding prompt. Answer only from the search results. Say “I don't have that information” when it is not there. Decline anything outside your products.
  4. Create the voice agent (Lesson 11). Short answers, one question at a time, a clear first message.
  5. Connect them (Lesson 12). Add a webhook tool that sends the caller's question to your production URL. Add a secret header.
  6. Open voice.html and talk to your agent.
  7. Test, fix, and test again using the table below.
Starter prompt for the n8n agentYou are a product expert for our store. Use the search tool to find product information. Search before every answer about a product. Answer only with facts returned by the search tool. Always mention the product name with any price or specification. If the tool does not return the answer, say "I don't have that information." If the question is not about our products, say you can only help with our products. For questions comparing two products, search for each one separately. Keep every answer to two short sentences.

The test

Write 20 questions before you start fixing anything: 17 about your products and 3 that are out of scope (for example, “What is the weather like?”, “Tell me a joke”, “Which phone should I buy?” if you sell kitchen items). Mix easy and tricky: price, features, comparisons, a product that does not exist, a misspelled name.

For each question, write the correct answer from your file first. Then ask the agent and mark it.

How to score In-scope questions: 17, so you need at least 15 correct (15 ÷ 17 is 88%, while 14 is 82%, which falls short). Out-of-scope questions: 3 of 3 must be declined. A “correct” answer has the right fact for the right product. A confident wrong price is a fail, even if it sounds good.

What to hand in

Before you share anything Open your exported workflow and search it for any key, password or secret header. Remove them. Credentials should live in n8n only.

How it will be judged

AreaStrong work looks like
CorrectnessAt least 85% of in-scope answers right, with the right product attached to each fact
Staying in scopeAll out-of-scope questions politely declined, with no invented answers
Voice qualityShort, natural replies and a reasonable pause before answering
Testing20 written questions, honest results, and fixes tied to the failing layer
SafetyNo secrets in files, a secured webhook

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. What are the two pass conditions for the project?

Correctness and staying in scope are both required.

2. A question fails because the wrong product was retrieved. Which layer do you fix first?

If retrieval is wrong, no prompt can rescue the answer.

3. A confident answer gives the wrong price. How is it marked?

A confident wrong answer is the worst kind of error.

4. The tool works in n8n but never fires from the voice agent. What do you check?

Test URLs only work while n8n is listening.

5. What must you remove from a workflow before sharing it?

Secrets belong in credentials, not in files you hand in.

Glossary

In scope
A question the agent should be able to answer from its data.
Out of scope
A question the agent should politely decline.
Test set
A fixed list of questions with known right answers, used to measure quality.
Grounding prompt
Instructions telling the agent to answer only from retrieved information.
Regression
A fix that breaks something that used to work. Re-run the whole test after every change.

Recap and what comes next

  1. The Product Expert combines Week 3: a voice agent calls a webhook, an n8n agent searches Supabase, and the answer comes back.
  2. Write the 20-question test first. Target at least 85% in scope and 3 of 3 declined out of scope.
  3. When something fails, find the layer: data, n8n prompt, voice agent or webhook. Fix one thing, then re-run the whole test.
