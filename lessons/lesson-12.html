Joining ElevenLabs and n8n: two patterns

Choose who runs the show, and use a webhook as the bridge.

About 45 minutes to read Core Download the slides

The big idea

There are two ways to join a voice agent to n8n. In Pattern A, n8n runs everything and borrows ElevenLabs for speech. In Pattern B, ElevenLabs runs the conversation and calls an n8n workflow when it needs something done.

By the end you can:

  • Compare the two integration patterns and choose one for a project.
  • Call ElevenLabs for text-to-speech and speech-to-text from an n8n workflow.
  • Give a voice agent a tool that triggers an n8n workflow.

Everyday comparison: who answers the phone Pattern A: you answer the phone yourself and ask a translator to help each time. Pattern B: a receptionist answers the phone and walks over to you only when something needs doing.

The bridge: a webhook

In Pattern B, the voice agent needs a way to ask n8n to do something. That bridge is the webhook from Lesson 9: an address that wakes up a workflow. The agent's “tool” is simply a call to that address.

  1. In n8n: add a Webhook node. Set the method to POST and choose a path. Set it to respond using a Respond to Webhook node, so the answer goes back to the agent.
  2. Do the work. For a callback booking, add a node that writes a row to a Google Sheet with the name, phone number and time.
  3. Reply. Add a Respond to Webhook node that returns a short answer such as {"result": "Callback booked for 3 pm"}.
  4. In ElevenLabs: open the agent's tools and add a webhook tool (some versions call it a server tool). Paste the n8n address, choose POST, and describe the tool in plain words: “Use this to book a callback. It needs the caller's name, phone number and preferred time.”
  5. Tell the agent when to use it, in its system prompt.
Test address or production address? The test URL in n8n only works while you are actively listening for a test event. A live agent needs the production URL, and the workflow must be active. This is the most common reason a tool “works in n8n but not from the agent”.
Lock the door A webhook is public to anyone who has the address. If the tool settings let you add a secret header, add one, and make the n8n Webhook node require it, so only your agent can trigger the workflow.

Pattern A in practice

In Pattern A, n8n calls ElevenLabs the same way it calls any API, using the HTTP Request node. The key goes in a header, as in Lesson 1.

  • Text to speech: a POST request that sends the reply text and chooses a voice. It returns audio.
  • Speech to text: a POST request that sends an audio file. It returns the written words.

The exact address, header names and fields are in the ElevenLabs API documentation, and they change from time to time. Always copy from the current docs. Store the key in an n8n credential, never inside the workflow text.

If something goes wrong

What you seeWhat it usually means
The agent says it could not reach the toolIt is calling the test URL, or the workflow is not active. Use the production URL and activate the workflow.
Error 404The path in the address does not match the Webhook node.
The tool is called but nothing is savedThe agent's inputs arrive under body. Check the field names in the Webhook node's output.
The agent never calls the toolThe tool description is vague, or the prompt does not say when to use it.
Error 401 from ElevenLabs (Pattern A)The key header is missing or wrong.

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. In Pattern A, who runs the whole workflow?

Pattern A is n8n orchestration.

2. What are the main strengths of Pattern B?

Pattern B lets ElevenLabs run the conversation natively. The price is two systems to keep in step.

3. What is the bridge between a voice agent and an n8n workflow in Pattern B?

The agent's tool calls the webhook address, which starts the workflow.

4. Which pattern is simplest and keeps everything in one place?

Pattern A has fewer moving parts and makes it easy to swap one service for another.

5. A webhook tool works when you test in n8n but fails from the live agent. What is the likely cause?

A live agent needs the production URL, and the workflow must be active.

Glossary

Pattern A
n8n orchestration: the whole workflow runs in n8n, which calls ElevenLabs for speech.
Pattern B
ElevenLabs orchestration: the voice agent runs the conversation and calls an n8n workflow as a tool.
Orchestration
Deciding which part runs, and in what order. Who is in charge.
Webhook tool
A tool for a voice agent that calls a webhook address to trigger a workflow.
Production URL
The webhook address that works while the workflow is active. Use it for live agents.
Test URL
The webhook address that only works while you are listening for a test event in n8n.
HTTP Request node
An n8n node that calls any web API, including ElevenLabs.
Respond to Webhook
An n8n node that sends an answer back to whoever called the webhook.

Recap and what comes next

  1. Pattern A: n8n runs everything and borrows ElevenLabs for speech. Simple, one place, easy to swap services.
  2. Pattern B: ElevenLabs runs the conversation and calls n8n as a tool. Lower latency, advanced voice features, more parts.
  3. A webhook is the bridge. Use the production URL for live agents, and lock the door with a secret header where you can.
