Self-hosted n8n and local models

Run n8n and an AI model on your own computer, and know when that is worth it.

About 50 minutes to read Core Download the slides

The big idea

So far you used n8n and models that live on other companies' computers. You can also run both on your own machine. You gain privacy and control. You take on setup, updates and a slower model.

By the end you can:

  • Explain the trade-offs of cloud versus self-hosted n8n and of cloud versus local models.
  • Run n8n locally with Docker or with npx.
  • Run a small model with Ollama and use it from an n8n agent.

Why run things yourself?

Everyday comparison: eating out or cooking at home A restaurant (cloud) is quick, someone else does the work, and you pay per meal. Cooking at home (self-hosted) gives you full control over ingredients and nobody sees what you eat, but you buy the equipment, shop, and wash up.
CloudSelf-hosted / local
SetupSign up and goInstall and configure
PrivacyData goes to another company's serversData can stay on your machine
CostSubscription or per useFree software, but you pay in electricity, hardware and time
Quality of modelStrongest models availableSmaller models. Good for simple jobs, weaker for hard ones
SpeedFastDepends on your computer. Can be slow without a good graphics card
UpkeepThe provider updates and backs upYou update, back up and fix

Run n8n on your computer

There are two common ways. Pick one.

Option 1: Docker

Docker runs programs in sealed boxes called containers, so they do not mess up your computer. Install Docker Desktop first, then run:

terminal
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n

Then open http://localhost:5678 in your browser. The -v n8n_data:... part saves your workflows. Without it, they vanish when the container stops.

Option 2: npx

If you have Node.js installed, one line is enough:

terminal
npx n8n

It downloads n8n and starts it on the same address. Docker is better for something you keep running. npx is quicker for trying it out.

Back up before you rely on it Your workflows and credentials live on your computer now. If the disk dies, so do they. Export important workflows as files and keep a copy elsewhere.

Run a model on your computer with Ollama

Ollama is a free program that downloads open models and runs them locally.

  1. Install Ollama from its website.
  2. Download a small model. Start small, because bigger models need more memory:
    terminal
    ollama pull llama3.2
  3. Try it in the terminal: ollama run llama3.2. Type a question and press Enter.
  4. Ollama also runs a small server at http://localhost:11434 that other programs, such as n8n, can talk to.
Model names change Model names and sizes change often. Look at the Ollama library for what is available now, and choose a small one if your computer has less than 16 GB of memory.

Connect n8n to Ollama

  1. In your agent, replace the chat model with the Ollama Chat Model node.
  2. Create an Ollama credential. The base URL depends on where n8n runs:
Where n8n runsBase URL to use
Directly on your computer (npx)http://localhost:11434
Inside Docker, Ollama on the computerhttp://host.docker.internal:11434

Why the difference? Inside a Docker box, “localhost” means the box itself, not your computer. host.docker.internal is the name for “the computer that is running this box”. On some Linux setups you may also need to add a flag so this name works.

  1. Choose the model name you pulled, for example llama3.2.
  2. Run your agent and compare the answer to the cloud model.
Tool use can be weaker Small local models are often worse at using tools. If your agent ignores a tool it could use, try a larger model or a model that is described as supporting tools.

Letting the outside world reach your n8n

A webhook on your own computer has an address like localhost, which only your computer can see. ElevenLabs cannot call it. A tunnel such as ngrok gives your local n8n a temporary public address.

terminal
ngrok http 5678

ngrok prints an address that starts with https://. Tell n8n to use it for its webhook addresses by setting the WEBHOOK_URL setting when you start n8n:

terminal
docker run -it --rm --name n8n -p 5678:5678 \
  -e WEBHOOK_URL=https://YOUR-NGROK-ADDRESS/ \
  -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n
A tunnel opens your computer to the internet Anyone with the address can reach your n8n. Use a strong n8n login, secure your webhooks with a secret header, and close the tunnel when you are not using it. Free tunnel addresses usually change every time you restart.

If something goes wrong

What you seeWhat it usually means
Port 5678 already in useAnother n8n is running. Stop it, or use a different port.
Workflows gone after restartThe volume (-v) was missing, so nothing was saved.
n8n cannot connect to OllamaWrong base URL for where n8n runs, or Ollama is not running.
Model not foundThe name in n8n does not match the one you pulled. Run ollama list.
Very slow answers or the computer freezesThe model is too big for your memory. Choose a smaller one.
The webhook address still says localhostWEBHOOK_URL was not set, or n8n was not restarted.

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. What is the main benefit of running a model locally?

Privacy and control are the reasons. Small local models are usually weaker.

2. Why does the docker run command include -v n8n_data:/home/node/.n8n?

Without a volume, the data disappears with the container.

3. n8n runs inside Docker and Ollama runs on your computer. Which base URL do you use?

Inside the box, localhost means the box itself. host.docker.internal means the computer.

4. What does a tunnel such as ngrok do?

It lets outside services, such as a voice agent, reach your local webhook.

5. Which is a real cost of self-hosting?

Control comes with responsibility.

Glossary

Self-hosted
Running software on a computer you control instead of the provider's servers.
Docker
A tool that runs programs in sealed boxes called containers.
Container
A sealed box holding a program and everything it needs.
Volume
A place outside the container where data is saved so it survives restarts.
npx
A Node.js command that downloads and runs a tool in one step.
Ollama
A free program that downloads and runs open AI models on your computer.
Local model
An AI model running on your own machine.
localhost
The address that means 'this computer'.
Tunnel (ngrok)
A service that gives a program on your computer a temporary public web address.
WEBHOOK_URL
An n8n setting that tells it which public address to show for webhooks.

Recap and what comes next

  1. Self-hosting trades convenience for privacy and control. You handle setup, updates and backups.
  2. n8n runs locally with Docker (use a volume) or npx. Ollama runs models locally. The base URL depends on whether n8n is inside Docker.
  3. Local models are usually smaller and slower, and weaker with tools. A tunnel exposes your local webhooks, so secure them.
