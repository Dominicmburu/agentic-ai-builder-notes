Supabase vectors and data ingest

Build the filing cabinet, load your data into it, and check that the search finds the right things.

About 55 minutes to read Integration Download the slides

The big idea

Supabase gives you a database that can store embeddings and search them by closeness. An n8n workflow reads your data, embeds it and files it there. Then you test the search before you trust it.

By the end you can:

  • Create a vector table in Supabase.
  • Build an n8n ingestion workflow that loads product data with metadata.
  • Check retrieval quality with a quick test.

What is Supabase?

Supabase is an online database service built on PostgreSQL. It has a free tier. An add-on called pgvector lets it store embeddings and find the closest ones.

Everyday comparison: a filing cabinet with a smart assistant A normal database is a cabinet where you find a file by its exact label. A vector database is a cabinet where you can say “bring me whatever is about returning shoes” and it brings the nearest matches.

Step 1: create the table

  1. Create a free Supabase account and a new project. Save the database password somewhere safe.
  2. Open the SQL Editor.
  3. Paste the code below and run it.
create-table.sql
-- Turn on the vector add-on
create extension if not exists vector;

-- The table that holds one row per chunk
create table documents (
  id bigserial primary key,
  content text,
  metadata jsonb,
  embedding vector(1536)
);

-- A search function that returns the closest chunks
create or replace function match_documents (
  query_embedding vector(1536),
  match_count int default 5,
  filter jsonb default '{}'
) returns table (
  id bigint,
  content text,
  metadata jsonb,
  similarity float
)
language sql stable
as $$
  select
    id, content, metadata,
    1 - (documents.embedding <=> query_embedding) as similarity
  from documents
  where metadata @> filter
  order by documents.embedding <=> query_embedding
  limit match_count;
$$;
The number 1536 must match your embedding model This is the length of each embedding. It must be identical to the length your embedding model produces. A common OpenAI embedding model produces 1536. If you pick another model, check its length in its documentation and change the number in both places. A mismatch is the most common error in this lesson.
Check the current n8n guide The n8n Supabase Vector Store node expects a table and function in a specific shape, and it can change between versions. The SQL above follows the common pattern. If the node complains, compare with the current n8n documentation for the Supabase Vector Store.

Step 2: connect n8n safely

In Supabase, open the project settings and find the project URL and the API keys. n8n's Supabase credential asks for the URL and a key.

The service key is a master key The service role key can read and write everything and skips the safety rules. Put it only inside an n8n credential. Never paste it into a web page, a chat, a screenshot or a public GitHub repository. If it leaks, rotate it in Supabase straight away.

Step 3: the ingestion workflow

  1. Read your data. Use a Google Sheets node, or the node that reads a spreadsheet file, to get one item per product.
  2. Make each row one readable chunk. Use an Edit Fields node to build a sentence that includes the product name, so context is never lost: 
    {{ $json.Name }} ({{ $json.Category }}). {{ $json.Description }} Price: {{ $json.Price }}.
  3. Add the Supabase Vector Store node with the operation to add documents. Pick your table and connect an embeddings model node and a document loader.
  4. Add metadata in the loader: the product name, category and any ID. Metadata lets you filter later and show where an answer came from.
  5. Run it once and open the table in Supabase. You should see one row per product, with text, metadata and a long embedding.
Run it only once per load Running the workflow twice adds every row twice, and duplicates will clutter your search results. If you need to start again, clear the table first in the SQL Editor with delete from documents;.

Step 4: test the retrieval

Never trust a search you have not tested. A quick method:

  1. Pick 10 products at random from your file.
  2. For each one, write a natural question about it, for example “How much is the quiet blender?”
  3. Ask each question through a search-only workflow (a vector store node set to retrieve, with no agent yet).
  4. Check whether the right product appears in the top 3 results.

Your exercise

If something goes wrong

What you seeWhat it usually means
An error about vector dimensions, such as “expected 1536 dimensions”The table's vector size does not match the embedding model. Change one so they agree, and re-create the table.
Error that the function match_documents does not existThe SQL did not run fully, or the function name differs from the one the node uses.
Permission or “row level security” errorYou used a key with fewer rights. For this course, use the service key inside the n8n credential only.
The same product appears several timesYou loaded twice. Clear the table and load once.
Search returns the wrong productChunks lack the product name or key words. Improve the chunk text and re-load.

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. What does pgvector add to a PostgreSQL database?

pgvector is the add-on that makes a normal database into a vector store.

2. Why must the vector size (such as 1536) match your embedding model?

A dimension mismatch is the most common error.

3. Why add metadata to each chunk?

Metadata such as the product name and category makes results traceable and filterable.

4. What is the safest place for the Supabase service key?

The service key is a master key. Keep it out of anything shared.

5. How do you check whether the search is good?

Test retrieval separately before adding an agent on top.

Glossary

Supabase
An online database service built on PostgreSQL, with a free tier.
PostgreSQL
A widely used database. Supabase is built on it.
pgvector
An add-on that lets PostgreSQL store and search embeddings.
Metadata
Extra labels attached to a chunk, such as product name and category.
Dimensions
The length of an embedding, for example 1536 numbers.
Service key
A master key for your Supabase project. Never share it.
SQL
The language used to talk to a database.
Top-k
How many of the closest chunks the search returns.

Recap and what comes next

  1. Supabase with pgvector is the vector store: one row per chunk, holding text, metadata and an embedding.
  2. The ingestion workflow reads data, builds a readable chunk for each row, adds metadata, embeds it and stores it. Load once.
  3. Test retrieval with 10 random products before adding an agent. Match the vector size to your embedding model and guard your service key.
