Week 1 · Lesson 5 · Project

Project: a tool-using assistant with memory

Build a small assistant, test it honestly, and report what failed.

About 40 minutes to read Project Download the slides

The brief

Build a chat assistant that remembers facts about the user, calls two tools only when it needs them, and passes a fixed test of 20 prompts.

This project brings together everything from Week 1: how an AI reads text, how to write instructions, how memory really works, and how tools work. You also practise the habit that separates builders from demo-makers: testing.

What you must hand in

Tick each box as you finish it. Your ticks are saved in this browser.

Target: at least 80% of the 20 prompts pass (16 or more).

How to build it, one stage at a time

Do not build everything at once. Finish each stage and test it before moving on.

  1. A chat that remembers. Re-send the history each turn, exactly as in Lesson 4. Test with a name and a favourite colour.
  2. A system prompt. Write the role and the rules, using the five-part recipe from Lesson 3. Include a rule such as “Do not call a tool when you can answer directly.”
  3. The calculator tool. Describe it clearly. Tell the AI to use it for any arithmetic.
  4. The second tool. A note-saver that stores a note, or a date tool that returns today's date.
  5. The test set. Run all 20 prompts, read the failures, improve the system prompt or tool descriptions, and run again. Change one thing at a time.

Where to build: any chat tool that supports tool calls, or a short script. n8n arrives next week, so do not use it yet.

Building your 20-prompt test set

A good test set covers the different things your assistant must do. Aim for roughly this mix:

GroupHow manyExampleWhat it proves
Needs the calculator7 or 8“What is 15% of 2400?” Expected: 360, with the calculator calledThe tool works and the answer is right
Needs no tool4“What is the capital of Kenya?” Expected: Nairobi, with no tool calledThe assistant does not over-use tools
Needs your second tool3 or 4“Save a note: buy paper on Friday.” Expected: note savedThe second tool works
Memory recall3 or 4After telling it your name earlier: “What is my name?”Facts survive across turns
Edge case1 or 2“What is 10 divided by 0?” Expected: a sensible explanation, no crashIt handles trouble gracefully

Be honest with your scores Decide what counts as a pass before you run the test. Changing the expected answers afterwards to make your score look better defeats the point. An honest 70% with a good failure report beats a suspicious 100%.

The report

Keep it to one page. Use this shape:

Report templatePass rate: __ out of 20 (__%) What my assistant can do: (one or two sentences) Failure 1: the prompt, what I expected, what happened, the likely cause, and my fix. Failure 2: the same. Failure 3: the same. What I would improve next:

A strong failure note looks like this: “Prompt 12, ‘What is 12.5% of 480?’ Expected the calculator. The assistant answered 60 without calling it. Likely cause: my system prompt said ‘use the calculator for maths’ but was not firm. Fix: changed it to ‘for ANY arithmetic, always call the calculator’. Pass rate went from 14 to 16 of 20.”

Troubleshooting

ProblemLikely causeTry this
The tool is never calledThe model does not support tools, or the tool description is vagueSwitch to a model that supports tools. Rewrite the description to say exactly when to use it.
A tool is called for easy questionsThe prompt says nothing about restraintAdd “Do not call a tool when you can answer directly.”
The tool gets the wrong inputsUnclear input descriptionsAdd an example to the input description
It forgets a factHistory was reset, or trimmed too muchPrint what is actually sent on each call
An error after trimming historyA tool result was sent without the message that asked for itWhen trimming, start the window at a user message
Error 429Free model rate limitSlow down between prompts, or use a paid model on test day

If you finish early

  • Add a third tool, such as the current time.
  • Summarise old messages instead of dropping them.
  • Show how many tokens each reply used.
  • Save the history to a file so the chat resumes tomorrow.

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. When should you write the expected result for a test prompt?

Deciding in advance keeps the score honest.

2. Your assistant answers a simple sum without calling the calculator. What is the best first fix?

Unclear instructions are the usual cause. Fix the prompt, then re-run the same test.

3. Which test prompt checks that the assistant does NOT over-use tools?

A good test set includes cases where the right move is to use no tool at all.

4. You scored 14 out of 20. The target is 80%. What do you do?

14 out of 20 is 70%. Improve the prompt or tools, then re-test honestly.

5. Why must the loop have a maximum number of rounds?

A safety limit stops runaway loops, which waste money and time.

Glossary

Test set
A fixed list of prompts with expected results, used to score an assistant fairly.
Pass rate
The share of test prompts the assistant got right, for example 16 of 20 is 80%.
Expected result
What you decided, before the test, would count as a correct answer.
Over-using tools
Calling a tool when a direct answer would do.
Failure report
A short write-up of the worst test failures, their causes and the fixes.

Recap and what comes next

  1. Build in stages: memory, then the system prompt, then each tool, then the test set.
  2. Write every test and its expected result before running it, and score honestly.
  3. Read the failures, change one thing at a time, and re-test. Report the three worst failures and what you did about them.
