Prompt engineering: giving clear instructions

How to write a prompt that works, and how to prove it works.

About 45 minutes to read Core Download the slides

The big idea

An AI only knows what you put in front of it. A good prompt is a clear set of instructions, and a good builder tests the prompt instead of guessing.

By the end you can:

  • Write a prompt with a system part, a user part and a stated output format.
  • Add examples and step-by-step reasoning when they help.
  • Test several versions of a prompt against the same set of cases and keep the best.

The AI starts fresh every time

Each time you call an AI, it sees only what you send in that call. It does not remember the last call.

Everyday comparison: the helper with no memory Imagine a very fast helper who forgets everything after each task. Every note you give them must be complete. If you say “do the same as yesterday”, they have no idea what that means. Writing a prompt is writing that complete note.

Two parts: system and user

System prompt

The standing instructions: who the AI is and what rules it follows. Like a job description.

User prompt

The specific request or data for this call. Like today's task.

The same system prompt can be reused for thousands of different user prompts. That is why we write it carefully, once.

The five-part recipe

  1. Role. Who is the AI acting as? “You are a customer-support triage assistant.”
  2. Task. What should it do, in one clear sentence? “Classify each message into one category.”
  3. Data. The material to work on, clearly separated from the instructions, for example after the words “Message:”.
  4. Rules. The limits. Say what to do, not only what to avoid. “The category must be billing, technical or general.”
  5. Format. Exactly what the reply must look like. “Reply with the category word only, in lowercase.”

Before and after

Weak promptWhat is this message about? Error 500 when I press Pay.

You will get a paragraph, different each time, that is hard for a program to use. Now compare:

Strong prompt: system partYou are a customer-support triage assistant. Classify each message into exactly one category: billing, technical or general. Reply with the category word only, in lowercase, with no punctuation.
Strong prompt: user partMessage: Error 500 when I press Pay. Category:

Now the answer is one word, in a predictable format, ready for a program to use.

Asking for structured output

When a program will read the answer, ask for JSON with exact key names, such as {"category": "billing", "confidence": "high"}. Keep the temperature low. Then check it is valid JSON before using it. Sometimes the AI adds a friendly sentence in front or wraps the answer in extra symbols, and a program trying to read that will break. If the check fails, try once more or flag it for a person. You practised the JSON rules in Lesson 1.

Test, do not guess

A prompt that worked on three examples tells you very little. The professional habit has four steps:

  1. Build a test set: a fixed list of example inputs with the correct answers (the “labels”).
  2. Run every prompt version on the same list.
  3. Score each version, for example 14 correct out of 20.
  4. Change one thing at a time, so you know what helped. Keep the best.
The cheating trap Never copy test messages into your few-shot examples. If the AI has seen the answers, your score is meaningless. Keep examples and test cases separate.
Where this is heading Prompt engineering is growing into context engineering: choosing everything the AI sees, including the conversation history and tool results. You meet that in Lesson 4 and again in Lesson 19.

For the curious: score a prompt automatically with Python

If you are comfortable running a script, this checks one prompt against all 20 messages and prints the score. Edit MODEL, RULES and EXAMPLES to try each version. A reply counts as correct only if it is exactly the category word.

import os, time, requests

API_KEY = os.environ["OPENROUTER_API_KEY"]
URL = "https://openrouter.ai/api/v1/chat/completions"
MODEL = "MODEL_ID"

TESTS = [
    ("I was charged twice for my subscription this month.", "billing"),
    ("The app crashes every time I open the settings page.", "technical"),
    ("What are your opening hours on Saturdays?", "general"),
    # ... add the other 17 messages and labels from the table above ...
]

RULES = ("You are a customer-support triage assistant. Classify each message into "
         "exactly one category: billing, technical or general. "
         "Reply with the category word only, in lowercase, with no punctuation.")
EXAMPLES = ""   # paste your few-shot examples here for version 3

def classify(message):
    resp = requests.post(
        URL,
        headers={"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"},
        json={"model": MODEL, "temperature": 0,
              "messages": [{"role": "system", "content": RULES + EXAMPLES},
                           {"role": "user", "content": f"Message: {message}\nCategory:"}]},
        timeout=60,
    )
    return resp.json()["choices"][0]["message"]["content"].strip().lower()

correct = 0
for message, label in TESTS:
    answer = classify(message)
    if answer == label:
        correct += 1
    else:
        print("MISS:", message, "| expected", label, "| got", answer[:40])
    time.sleep(0.5)
print(f"Score: {correct}/{len(TESTS)}")

Common mistakes

  • Tuning on the test set. Copying test messages into your examples inflates the score.
  • Changing many things at once. You cannot tell which change helped.
  • Vague goals such as “be helpful”. Say exactly what good looks like.
  • Trusting one run. If a score surprises you, run the set again.
  • Asking for JSON without checking it.

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. What does the AI remember from your previous call?

Each call starts fresh. That is why a prompt must be a complete note.

2. What is the difference between a system prompt and a user prompt?

Think job description (system) and today's task (user).

3. What are few-shot examples?

Showing a few finished examples is often faster than explaining in words.

4. Why must few-shot examples be kept out of your test set?

A fair test uses cases the AI has not been shown.

5. The AI returns JSON that your program will use. What should you do first?

Models sometimes add extra words or symbols around JSON, which makes a program fail.

Glossary

Prompt
The instructions and data you send to an AI.
System prompt
The standing role and rules for the AI, set once. Like a job description.
User prompt
The specific request or data for this call. Like today's task.
Few-shot examples
A few worked input-and-answer pairs placed in the prompt to show the AI what you want.
Structured output
A reply in a fixed format, such as JSON, that a program can read.
Test set
A fixed list of example inputs with the correct answers, used to score prompts fairly.
Label
The correct answer for an item in a test set.
Context engineering
Choosing everything the AI sees in a call, not only the wording of the instructions.

Recap and what comes next

  1. The AI starts fresh every call, so a prompt must be a complete note.
  2. Use the five parts: role, task, data, rules, format. Add examples when the format is hard to describe.
  3. Test every prompt version on the same fixed set, change one thing at a time, and never mix examples into the test set.
