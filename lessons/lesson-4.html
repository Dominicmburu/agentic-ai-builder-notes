Memory, context and tools: from chatbot to agent

Why a chat only seems to remember, and how an AI uses tools to act.

About 50 minutes to read Core Download the slides

The big idea

The AI does not remember your chat. The app re-sends the whole conversation every time. And an AI cannot do things by itself: it asks, and your app acts. Put those two ideas in a loop and you have an agent.

By the end you can:

  • Explain why a chat seems to have memory, and why the model does not.
  • Decide what to keep, summarise or drop when a conversation gets long.
  • Describe the agent loop and how a tool call works.

The illusion of memory

When you chat with an AI, it feels like it remembers what you said ten messages ago. It does not. Here is what really happens on every turn:

  1. You type a new message.
  2. The app adds it to the whole conversation so far.
  3. The app sends everything to the AI.
  4. The AI reads it from the very top, then writes the next reply.
Everyday comparison: the notebook Imagine a helper who forgets everything the moment you walk away. To get around that, every time you speak to them you hand over a notebook and say “read this from page one, then answer.” The notebook is the memory. The helper has none.

The proof: if the app stops sending message 1, the AI has never heard of it.

The context window is a desk

Last lesson you met the context window, the maximum number of tokens in one call. Everything in the conversation counts against it: your instructions, every earlier message, tool results, and the reply being written.

Everyday comparison: the desk The context window is the size of the desk. Only what fits on the desk can be read. Pile on too much and either something falls off, or the helper gets distracted by the mess.

Two problems follow. If you go over the limit, the call fails or the oldest text is cut. And even below the limit, a desk piled with irrelevant papers can make answers less focused. More is not always better.

Tools: how an AI acts in the world

On its own an AI can only produce text. It cannot check a calendar, calculate reliably, look at a website or send an email. A tool fixes that. A tool is a small function in your app that you describe to the AI: its name, what it does, and what information it needs.

Everyday comparison: phone a friend You are in a quiz show and do not know the answer, so you phone a friend. The AI cannot make the call itself. It says “please phone the calculator and ask for 1234 times 5678.” Your app makes the call and reads back the result.
The model asks. Your app acts.

The AI never runs a tool. It writes a structured request: call this tool with these inputs. Your app runs the tool and sends the result back. Then the AI writes the final answer using that result.

For the curious: what a tool call looks like in code

This is the list of messages for the example above. The AI's request arrives as a JSON string, which your app must read.

[
  {"role": "user", "content": "What is 1234 times 5678?"},
  {"role": "assistant", "content": null, "tool_calls": [
    {"id": "call_1", "type": "function",
     "function": {"name": "calculator", "arguments": "{\"expression\": \"1234 * 5678\"}"}}
  ]},
  {"role": "tool", "tool_call_id": "call_1", "content": "7006652"},
  {"role": "assistant", "content": "1234 times 5678 is 7,006,652."}
]

Not every AI model supports tools. When you choose a model for tool work, look for one that says it does.

Your exercise: prove the memory is an illusion

The goal is to see with your own eyes that the AI only knows what is re-sent. Choose either version.

Version A, no code: be the AI

Work in pairs. One person plays the app, the other plays the AI.

  1. The app writes each message on its own card: “Hi, my name is Wanjiru and my favourite fruit is pineapple.” is card 1.
  2. Add five more cards, for example: a Python question, a library name, what an API does, a study tip, and finally “What is my name and favourite fruit?”
  3. Round 1, full history. The app hands the AI all the cards. The AI answers the last question using only the cards it was given.
  4. Round 2, trimmed history. The app hands over only the last four cards. Ask the same final question.
  5. Swap roles and repeat with different facts.

Version B, with code

This chat loop re-sends the history on every turn. First run it with MAX_MESSAGES = None and tell it your name in the first message. Later ask “What is my name?” Then set MAX_MESSAGES = 6 and run the same test.

import os
import requests

API_KEY = os.environ["OPENROUTER_API_KEY"]
URL = "https://openrouter.ai/api/v1/chat/completions"
MODEL = "MODEL_ID"
SYSTEM = {"role": "system", "content": "You are a friendly assistant. Keep answers to two sentences."}

MAX_MESSAGES = None   # try None first, then 6

def ask(messages):
    resp = requests.post(
        URL,
        headers={"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"},
        json={"model": MODEL, "temperature": 0, "messages": messages},
        timeout=60,
    )
    return resp.json()["choices"][0]["message"]["content"].strip()

history = []
print("Type quit to stop.")
while True:
    text = input("You: ").strip()
    if text.lower() == "quit":
        break
    history.append({"role": "user", "content": text})
    window = history if MAX_MESSAGES is None else history[-MAX_MESSAGES:]
    reply = ask([SYSTEM] + window)     # the system prompt is added fresh every time
    history.append({"role": "assistant", "content": reply})
    print("AI:", reply)

Hand in: both final answers, and a short explanation in your own words of why the second one forgot. A strong answer also notices the cost: sending the full history uses more tokens on every turn.

Common mistakes

  • Thinking the AI learns from the chat. It does not change between calls.
  • Trimming by message count while a few very long messages still overflow the desk.
  • Cutting the system prompt when trimming. Always add it fresh.
  • Believing the AI runs the tool itself.
  • Forgetting a limit on how many loop rounds are allowed.

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. Why does a chat seem to remember what you said earlier?

The AI is stateless. The app supplies the memory by re-sending the history.

2. If the app stops sending message 1, what does the AI know about it?

The AI only sees what is in the current call.

3. A long conversation no longer fits the context window. Which is NOT a standard strategy?

Trimming, summarising and storing-and-retrieving are the three strategies. Memory is not something the AI can try harder at.

4. Who actually runs a tool in an agent?

The model asks for a tool in a structured request. The app runs it and returns the result.

5. Which sequence is the agent loop?

That four-step loop is the heart of every agent.

Glossary

Stateless
Keeping nothing between calls. An AI model is stateless; the app supplies the memory.
Conversation history
The list of earlier messages that the app re-sends on each turn.
Context window
The fixed token limit for one call. Instructions, history, tool results and the reply all count.
Summarise
Replace old messages with a short recap to save space.
Tool
A function in your app that the AI can ask for, such as a calculator or a search.
Tool call
A structured request from the AI saying which tool to run and with what inputs.
Agent loop
The repeating cycle of decide, act with a tool, observe the result, and continue until the goal is met.
Agent
An AI that runs tools in a loop to reach a goal.

Recap and what comes next

  1. A chat only seems to remember. The app re-sends the whole conversation each time.
  2. The context window is a desk. Decide what to keep, summarise or drop.
  3. A tool call is a structured request: the model asks, your app acts, and the result goes back.
  4. An agent runs that cycle in a loop until the goal is met, with a safety limit.
