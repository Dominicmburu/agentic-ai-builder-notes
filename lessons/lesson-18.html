MCP: a standard plug for tools

How agents connect to outside tools through one common standard, and how to do it safely.

About 50 minutes to read Core Download the slides

The big idea

MCP (Model Context Protocol) is a standard plug. Any AI app that speaks MCP can use any tool that speaks MCP, without custom wiring for each pair.

By the end you can:

  • Explain MCP and the roles of host, client and server.
  • Choose between the ways MCP connects.
  • Connect an MCP server to an n8n agent, or expose your own workflows as an MCP server.
  • Judge whether an MCP server is safe to trust.

The problem MCP solves

Everyday comparison: the phone charger Before USB-C, every phone had its own charger. You needed a drawer full of them. With one standard plug, any charger fits any phone. MCP is that standard plug for AI tools: write a tool once, and any compatible agent can use it.

Three roles

  • Host: the AI application the person uses, such as an n8n agent or a chat app.
  • Client: the part inside the host that speaks MCP and keeps one connection to each server.
  • Server: a program that offers tools (and sometimes data) in the standard format. “Server” just means “the side that offers things”. It may run on your own computer.

How they connect: transports

TransportWhat it isUse it for
stdioThe host starts the server as a program on the same computer and they talk through it directlyLocal tools on your own machine. Not available to cloud-only apps
Streamable HTTPThe server lives at a web address and talks over normal web requestsRemote servers. The current recommended way over the web
SSEAn older web methodStill seen in the wild, but deprecated. Prefer Streamable HTTP when you have the choice

MCP in n8n: three routes

1. Use an MCP server as a tool

Add the MCP Client Tool node to your AI Agent. Give it the server's address and credentials. The agent can now use every tool that server offers.

2. Offer your workflows as tools

Start a workflow with the MCP Server Trigger node and attach tools to it. n8n gives you an address that other MCP clients, like a chat app, can connect to.

3. Control n8n itself

n8n can also expose your instance to MCP clients so they can find and run chosen workflows. This is a switch in the instance settings, and you choose which workflows are available.

Names and menus move MCP support in n8n is relatively new, and node names, settings and options are still changing. Check the current n8n documentation if a name does not match what you see.

Connect a server to your agent

  1. Open an AI Agent workflow from earlier.
  2. Under Tool, add the MCP Client Tool node.
  3. Set the endpoint (the server's web address) and the transport the server supports.
  4. Choose authentication if the server needs it. Use a credential, not text typed into the node.
  5. Choose which of the server's tools the agent may use. Start with only what you need.
  6. Ask the agent a question that needs the tool and open the execution to confirm it called it.

Trust and safety

An MCP server is code you are inviting in A server can read what you send it, and what it sends back goes straight into your agent's thinking. A careless or malicious server can leak data or slip hidden instructions into its replies.

Lesson 19 explains the worst combination of risks, called the lethal trifecta.

Your exercise

Connect an MCP server to an n8n agent and ask it a question that needs the tool. Then, if time allows, expose one workflow of your own as an MCP server.

  1. Pick a safe, well-known server your teacher suggests. A read-only one is best.
  2. Add it to the agent with the MCP Client Tool node and allow one or two tools.
  3. Ask a question that needs it. Open the execution and write down which tool the agent called and what it sent.
  4. Ask a question that does not need it. Did the agent correctly leave it alone?

Glossary

MCP
Model Context Protocol. A standard way for AI apps to use outside tools.
Host
The AI application that wants to use tools.
MCP client
The part inside the host that speaks MCP and connects to servers.
MCP server
A program that offers tools in the MCP standard.
Transport
The way client and server talk: stdio, Streamable HTTP or SSE.
stdio
Local transport: the host starts the server on the same computer.
Streamable HTTP
The current recommended transport for remote servers.
SSE
An older web transport, now deprecated.
MCP Client Tool
The n8n node that lets an agent use a server's tools.
MCP Server Trigger
The n8n node that offers your workflows as tools to other MCP clients.
Least privilege
Giving only the permissions that the job needs.

Recap and what comes next

  1. MCP is the standard plug: hosts contain clients, clients connect to servers, and servers offer tools.
  2. Transports: stdio for local programs, Streamable HTTP for remote servers, SSE is older and deprecated.
  3. In n8n you can use servers (MCP Client Tool), offer workflows as a server (MCP Server Trigger), or expose your instance. Trust only servers you can vouch for, and allow the fewest tools.
