Project: Daily Portfolio Rebalancer

A scheduled workflow that checks a portfolio every day, measures drift and emails a summary.

About 55 minutes to read Project Download the slides

The brief

Build a workflow that runs every day, reads the holdings of a practice portfolio, measures how far each one has drifted from its target, and emails a summary.
Learning exercise only Run this on paper or test data only. It is a learning exercise, not financial advice, and it must never place real trades.

The idea in plain words

Imagine a fruit basket plan: 40% mangoes, 35% oranges, 25% bananas, by value. Prices change, so after a while the mangoes might be worth more than 40% of the basket. The basket has drifted from the plan. Rebalancing means buying and selling a little to get back to the plan.

Your workflow does the checking automatically every day, and an AI agent writes a friendly summary.

What you must hand in

Your instructor's starting files are Equity Portfolio Rebalancer.json (a workflow you can import into n8n) and portfolio.xlsx (the holdings). Upload the spreadsheet to Google Sheets. Column names in your files may differ from the ones used below, so adjust to match.

The maths, with a worked example

Four small calculations. Start with a practice portfolio worth $10,000:

AssetSharesPriceValueTarget
AAA80$50$4,00040%
BBB35$100$3,50035%
CCC250$10$2,50025%
Total$10,000100%
  1. Value = shares × price. (AAA: 80 × $50 = $4,000)
  2. Weight = value ÷ total value. (AAA: $4,000 ÷ $10,000 = 40%)
  3. Drift = weight − target weight, in percentage points. A positive number means overweight.
  4. Flag the asset if the drift, ignoring its sign, is bigger than your threshold (for example 3 points).

Proposed trade for a flagged asset: work out the value it should have (target × total), subtract what it has now, and divide by the price. A positive result means buy, a negative one means sell.

A drifted example

Suppose AAA rises 30%, from $50 to $65, and nothing else moves. The total becomes $11,200.

AssetValueWeightTargetDriftResult at 3-point threshold
AAA$5,20046.43%40%+6.43Flagged: sell about 11.1 shares
BBB$3,50031.25%35%−3.75Flagged: buy about 4.2 shares
CCC$2,50022.32%25%−2.68Hold (below the threshold)

Check the AAA trade: the target value is 40% of $11,200 = $4,480. It holds $5,200, so it sells $720 worth, which is $720 ÷ $65 = 11.1 shares.

The workflow, step by step

  1. Schedule Trigger. Set it to run once a day at a time you choose.
  2. Google Sheets, get rows. Read your holdings. Check that you get one item per asset.
  3. Code node, calculate. Does the four calculations above. A ready-made version follows. If you prefer not to use code, you can build the same sums with the Edit Fields node.
  4. AI Agent. Give it the results as text with {{ JSON.stringify($input.all().map(i => i.json)) }} and ask for a short, plain summary.
  5. Gmail, send. Send the summary to yourself while testing.

The Code node

Add a Code node, set the language to JavaScript, and the mode to run once for all items. It expects columns named ticker, shares, price and target. A target can be a decimal like 0.4 or a percentage like 40%. To change the threshold, edit the number on the first line.

code-node.js
const THRESHOLD = 0.03; // flag assets that drift more than 3 percentage points

// Turns "$1,234.50" or "40%" into a plain number
const toNumber = (v) => Number(String(v).replace(/[^0-9.\-]/g, ""));

const rows = $input.all().map((item) => {
  let target = toNumber(item.json.target);
  if (target > 1) target = target / 100; // 40 means 40%
  return {
    ticker: item.json.ticker,
    shares: toNumber(item.json.shares),
    price: toNumber(item.json.price),
    target: target,
  };
});

const total = rows.reduce((sum, r) => sum + r.shares * r.price, 0);

return rows.map((r) => {
  const value = r.shares * r.price;
  const weight = value / total;
  const drift = weight - r.target;
  const flagged = Math.abs(drift) > THRESHOLD;
  const tradeValue = r.target * total - value;
  return {
    json: {
      ticker: r.ticker,
      value: Math.round(value * 100) / 100,
      weight: Math.round(weight * 10000) / 10000,
      target: r.target,
      drift: Math.round(drift * 10000) / 10000,
      flagged: flagged,
      action: !flagged ? "hold" : tradeValue > 0 ? "buy" : "sell",
      tradeShares: flagged ? Math.round(Math.abs(tradeValue / r.price) * 10) / 10 : 0,
    },
  };
});

Testing with simulated price changes

You need at least five simulated price changes. Change the prices in your test sheet, run the workflow and check the result. Using the practice portfolio above and a 3-point threshold, here is what you should see:

TestPrice changeExpected result
1AAA up 10%No flags. The biggest drift is 2.3 points, under the threshold
2BBB down 10%No flags. The biggest drift is 2.4 points
3CCC doublesAll flagged. Buy about 20.0 AAA and 8.8 BBB, sell about 93.8 CCC
4Every price down 5%No flags. All weights stay the same, so nothing drifts
5AAA up 30%AAA flagged: sell about 11.1. BBB flagged: buy about 4.2. CCC holds
6AAA up 10%, threshold lowered to 2 pointsAAA flagged: sell about 4.4. Shows why the threshold matters

If your numbers differ, find out why. A common cause is a target stored as 40% text instead of a number (the code above handles that), or a price column read as text.

If something goes wrong

What you seeWhat it usually means

Weights do not add up to 100%A holding is missing from the sheet, or the targets do not total 100%.
The Code node returns an errorIt must return a list of objects, each with a json field.
The schedule did not runThe workflow is not active, or the time zone differs from yours.

Quick quiz

Click an answer. You will see right away if it was correct, and why.

1. A portfolio is worth $10,000. Asset A is worth $4,500 and its target is 40%. What is its drift?

Weight is 4,500 / 10,000 = 45%. Drift = 45% - 40% = +5 points.

2. The threshold is 3 points and an asset has drifted 2.4 points. What happens?

Only drift bigger than the threshold, ignoring the sign, is flagged.

3. All prices fall by exactly 5%. Do the weights change?

Weights are shares of the total, and equal moves leave the shares unchanged.

4. Which step turns the calculated numbers into a readable note?

The agent writes the summary from the numbers it is given. It should not invent any.

5. Where should you run this project?

Never connect a learning workflow to real trading.

Glossary

Portfolio
A collection of investments held together. In this project, practice data only.
Weight
An asset's value as a share of the whole portfolio's value.
Target weight
The share you planned for an asset.
Drift
The difference between an asset's weight and its target, in percentage points.
Threshold
The drift size above which an asset is flagged.
Rebalancing
Buying and selling to bring weights back to their targets.
Schedule trigger
An n8n node that starts a workflow at set times, such as once a day.
Code node
An n8n node where you write a small piece of code to process data.

Recap and what comes next

  1. A schedule trigger makes a workflow run by itself every day.
  2. Weight = value / total. Drift = weight - target. Flag when the drift passes the threshold.
  3. Test with simulated price changes and compare to expected results before trusting any workflow.
  4. This is practice data only, never financial advice.
